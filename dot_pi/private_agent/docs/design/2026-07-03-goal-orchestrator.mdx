# Goal orchestrator — L-tier fire-and-forget autonomous loop

<Callout type="success" title="Status: accepted — supersedes the pi-ralph hat-loop">
The L-tier orchestration slot is **goal**, engine `@misunders2d/pi-goal`. It replaces the pi-ralph
hat-loop (`2026-07-03-ralph-migration-dev-lifecycle.mdx`, now superseded). "goal" is the ROLE (one
long autonomous single-slice task); pi-goal is the engine. This doc is the contract of record.
</Callout>

## Problem

The L-tier slot needs one autonomous, long-running slice: describe an outcome, walk away, come back
to verified-done. The prior engine (pi-ralph) modelled this as fresh-session hat roles with a disk
scratchpad. It crashed in practice — the harness rejected a `ctx` captured before `newSession()`
("ctx is stale after session replacement") — and its completion gate was a hat's judgement, not
independent evidence.

## What "ralph" actually needs from the harness

The L-tier autonomous loop is defined by three primitives, everything else is flavour:

1. **Self-triggered turn** — the agent starts the next iteration without a human (`sendMessage({
   triggerTurn })`). This IS the loop.
2. **Durable state outside context** — progress survives compaction / reload / resume.
3. **Full-environment turns** — extensions + subagents stay LIVE so the loop can delegate.

pi-ralph added a fourth (context reset per iteration via `newSession()`) and a policy layer (hats,
event bus, scratchpad). Those are pi-ralph opinions, not the role. pi-goal keeps the three primitives
and trades the reset for compaction-proof state.

## Decision

<Decision title="Adopt @misunders2d/pi-goal as the L-tier engine" status="accepted">
Engine `@misunders2d/pi-goal`, **in-process**: the loop drives the SAME session via `pi.sendMessage({
triggerTurn: true, deliverAs: "followUp" })`. No pi subprocess, no `--no-extensions` — so pi-rules,
skills, and the `Agent` (subagent) tool stay live in every worker turn. Context is NOT reset per
iteration; context bloat is fought with durable, compaction-proof state instead.
</Decision>

### Execution model — fire-and-forget goal

- **One approved contract**, derived in FASE 2 from the FASE-1 spec: outcome + done-conditions +
  phases + **authority envelope** + tier-routing rules. Approve once.
- **Autonomous** continue → recover → verify until **evidence-backed complete** or genuinely blocked.
- Bounded recovery, stale-turn protection, doom-loop detection.
- **Completion gate = constrained verifier + isolated auditor.** The auditor runs in a fresh
  in-memory pi session with NO extensions / skills / prompt templates / worker transcript / mutation
  tools; it re-checks each criterion and runs approved verification checks by ID (no shell). Narrative
  alone never completes a goal.
- **Interruptions only for** `CREDENTIAL` / `DECISION` / `RISK` / `BLOCKER`. Informational questions
  (status, why-recovering) do not mutate the contract.
- One active goal per session. TUI-only (`-p` / JSON / RPC refuse to start it).

### Delegation + fault-tolerance routing

Delegation is NOT lost by moving off pi-ralph. Because pi-goal is in-process, the `Agent` tool is
live in every worker turn — the driving agent DELEGATES to worker subagents exactly like one-shot.
The only thing pi-ralph did that pi-goal does not is AUTO-route tiers via hats. That routing now lives
in the **FASE-2 contract**: the contract states, e.g. "low-tolerance slice (auth / secrets / migration
/ schema / money / data-deletion) → spawn `<vertical>-frontier-worker`; standard → `<vertical>-worker`".
The authority envelope (typed per-action permission) is the natural home for this — risk is
first-class, so tier-by-risk and mutate-by-authority sit in one contract.

### Safety

- The original user outcome stays authoritative; only user steering can expand outcome or authority.
- Workspace writes are limited to the starting directory. Mutating / external actions outside the
  typed authority envelope stop as `RISK`.
- Durable evidence stores metadata / hashes / statuses / sanitized summaries — never raw tool output,
  secrets, tokens, or auth-file contents.
- Goal mode never weakens Pi's existing permission or confirmation gates.

## Boundary vs the other flows

- **one-shot (S/M)** — short delegation, no contract file.
- **goal (L)** — THIS: one deep autonomous slice, contract + audit.
- **fleet (XL)** — DAG-of-DAG, judge-gated, greenfield.
- **dynamic-workflow (sweep)** — wide SAFE-only fan-out, capped standard tier
  (`2026-07-03-dynamic-workflow-flow.mdx`).

The L-tier decision happens in the main agent PRE-loop (hard human gate); pi-goal's own setup/planning
happens only AFTER approval, INSIDE the run, and never makes the level decision.

## Migration note

Disable/uninstall the old `/goal` (if any) before installing — Pi must expose exactly one `/goal`.
pi-ralph (`npm:pi-ralph`) and the `ralph-preset` skill are retired; the `goal-sweep` skill is renamed
`dynamic-workflow`.
